# 中文 Codex 兼容规则

本文件是正式技能的统一兼容层。它不会替代、缩写或删除原技能的方法论。执行任何引用本文件的技能时，先应用这里的规则，再完整执行该技能及其按需引用的支持文件。

## 面向中文创作者

- 默认使用简体中文与用户交流；用户指定其他语言时遵从用户选择。
- 把用户视为产品与内容的最终决策者。先说明结果、影响和可见变化，再补充必要的工程细节。
- 接受中文自然语言、中文项目名、中文文件名、中文 Git 提交和中文 Issue。代码标识符、命令、API 名称及行业术语保持原样，首次出现时用中文解释。
- 需要用户判断界面、文案、流程或信息层级时，优先提供可查看的预览或可运行原型；不要只用抽象术语描述。
- 不因为用户没有使用工程术语就缩小需求。主动把中文业务表达映射为代码、测试、文档和验收条件。

## Codex 技能调用映射

- 原文中的 `/skill-name` 在 Codex 中解释为 `$skill-name`。
- 原文中的“调用 Skill tool”表示：从当前可用技能中加载并使用指定技能。不要虚构一个不存在的工具调用，也不要假装已经加载。
- 如果引用的技能不可用，说明缺少哪个技能，并在不丢失核心流程的前提下直接执行等价步骤。
- “后台代理”或“子代理”表示使用当前环境实际提供的协作能力。若环境不支持，则在当前会话顺序执行，并明确说明没有并行。
- 用户显式调用专用技能时完整读取其 `SKILL.md`；支持文件仍按原技能的渐进披露规则按需读取。

## Windows 与工具选择

- Windows 上默认使用 PowerShell；Linux/macOS 上使用其原生 shell。只有项目明确要求 Bash，或 Git Bash/WSL 已可用时，才在 Windows 上执行 Bash 脚本。
- 搜索文件和文本优先使用 `rg`。修改文本文件优先使用 Codex 的补丁编辑能力，避免用 shell 拼接覆盖文件。
- Windows 文件操作使用绝对路径和 `-LiteralPath`；递归删除、移动或覆盖前必须解析并核对目标范围。
- `wizard` 与 `diagnosing-bugs` 同时提供 `.ps1` 和 `.sh` 模板；在 Windows 上优先选 `.ps1`。
- 展示命令时给出适合当前操作系统的可复制版本，不要求中文创作者自行翻译 shell 语法。

## 授权和安全边界

- 技能中的“提交”“发布”“创建 Issue”“关闭 Issue”“继续 rebase”“设置 Secrets”“写入 `.env`”是工作流步骤，不自动构成用户授权。
- 执行外部写入、Git 提交或推送前，必须确认用户当前请求或仓库规则已经明确授权该动作。提交授权不等于推送授权，测试环境授权不等于生产环境授权。
- 不把 Token、密码、Cookie、个人数据或完整认证头写入对话、提交、日志和生成文档。必须展示时使用 `<REDACTED>`。
- 遇到未知远程变化、无法确认的冲突意图、敏感扫描命中或验证失败时停止对应写入，不绕过门禁。
- 原技能与本兼容层冲突时：用户最新明确指令优先，其次是更严格的项目规则和安全边界，再其次才是技能的默认工作流。

## 内容完整性

- `skills/engineering` 和 `skills/productivity` 中的25个正式技能是适配范围；`in-progress` 与 `misc` 保留在仓库中，但不作为正式安装集合。
- 保留原技能的步骤、例子、术语、模板、参考文件与设计理由。中文适配可以增加解释和平台映射，不以摘要替换正文。
- 上游更新时先同步原内容，再重新运行适配和验证脚本；发现新的正式技能或支持文件时必须显式纳入验证。
